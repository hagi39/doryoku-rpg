# 努力RPG

設計書『努力RPG_設計書_ClaudeCode実装用.md』の実装。
`src/` を編集し、ビルドで単一HTML `dist/努力RPG.html` を作る。配布物はこの1ファイルだけ。

## 使い方

```sh
npm run build   # src/ → dist/努力RPG.html
npm test        # ルールとデータの自動テスト
npm run check   # ビルド + テスト + 成果物の構文/自己完結チェック
```

## 決まっていること

- **配布**: 単一HTMLのまま、`file://` でも https 配信でも動くようにする(両対応)
- **AI**: Anthropic Messages API を fetch で直接呼ぶ。ヘッダ `anthropic-dangerous-direct-browser-access: true` が必須
- **既定モデル**: `claude-haiku-4-5`(設定タブで Sonnet 5 / Opus 5 に変更可)
- **APIキー**: 設定タブで入力し localStorage に保存。HTMLファイルには焼き込まない

### `file://` で使うときの注意

localStorage はオリジン単位で保存されるため、更新版のHTMLを別の場所に置くと進捗が読めなくなることがある。
設定タブのバックアップ(書き出し/読み込み)を必ず経由すること。この点は設定タブにも警告を出している。

## ディレクトリ

```
build.mjs              ビルド(連結して1枚のHTMLにする)
src/index.html         テンプレート(<!--@CSS--> / <!--@JS--> を差し替える)
src/css/               base(トークン・リセット) / layout(枠) / components(部品) / tree / quiz / learn
src/js/core/           util, rules(ゲームのルール), validate, layout, store, actions, quiz(採点・合否・診断)
src/js/data/           tree-data(145スキル)
src/js/api/claude.js   Anthropic API クライアント + 接続テスト + モック
src/js/api/quiz-gen.js AIへの出題指示(解放・復習・診断・講評)
src/js/api/material-gen.js 教材(要点・例題・つまずき)と確認問題の指示
src/js/ui/             shell(土台)、quiz-ui(出題画面)、tests(テストの流れ)、tab-*(6タブ)
test/run-tests.mjs     ルール・データ・保存・採点の検証 + AIモックでの通し動作
test/check-bundle.mjs  成果物の構文と自己完結の検証
```

ビルドに新しいJS/CSSを足すときは `build.mjs` の `JS_FILES` / `CSS_FILES` に順番どおり追加する
(ES modules は `file://` で読めないため、すべて classic script として連結している)。

## 設計書で未確定だった点の判断

1. **サビの再計算**: 状態として持たず、表示のたびに `polishedAt` からの経過日数で計算する(`rules.js`)
2. **「使ったスキル」の回復**: タグを付けたスキルとその直接の前提を、サビ 0.7 ぶん回復させる
2b. **ツリーの並べ方**: 段ごとに親の位置の平均(重心)で子を並べ替えて線の交差を減らす(`layout.js`)。1段が3個を超えると折り返す
3. **世界地図**: 国ごとの輪郭SVGではなく、大陸の簡略輪郭 + 代表点(経緯度→正距円筒図法)の丸印で描く予定(P6)
4. **localStorage 容量**: 目安5MB。設定タブに使用量を表示。復習リストは300問、教材はスキルごと1件に制限する
5. **記述式の採点**(`quiz.js`): 全角・半角、空白、「」、マイナスの書き方をそろえて比べる。小数と分数(0.5 = 1/2 = 2分の1)、指数表記は同じ値なら正解。割り切れない値は、小数第2位以上まで書いて四捨五入が一致すれば正解(1/3 → 0.33 は正解、0.3 は不正解)。因数分解は因数の並びがちがっても正解
6. **合格ライン**: 「この問題がおかしい」で外した問題は分母から除き、必要な正解数は切り上げる(解放テストは4問中3問、3問に減ったら3問)。有効な問題が1問以下なら判定しない。外すボタンは解答中だけ押せる(答えを見てから外せないようにするため)
7. **復習テスト**: 3問(選択2・記述1)中2問で合格。合格は「復習のみ」の記録と同じ扱い(サビが0、磨いた回数+1、経験値)。入口はツリーのスキル画面と記録タブ
8. **診断**: 「ここまでできる」スキルは1つ選ぶ。そのスキルと前提から均等に選び、1つ先を1問足して最大6問。正解したスキルは他ツリーの前提ごと解放する。結果はツリーごとに `progress.diagnoses` に残し、講評は押したときだけ作る
9. **確認問題(教材から)と復習リストの画面**は、学ぶタブと一緒に P5 で作る(P4 では、まちがえた問題を復習リストに保存するところまで)
10. **確認問題と復習リストの経験値**: 経験値だけ入れ、パラメーターは上げず、サビも落とさない。
    サビが落ちるのは「記録」と「復習テスト」の2つだけにして、ルールを分かりやすくしている。
    どちらも1問正解につき4xp。確認問題は「1日1スキル1回だけ」(`progress.daily`)で、2回目からは0
11. **復習の出し方**: 克服済みは出さず、最後に解いた日が古い順 → まちがいが多い順で最大10問。
    答えの位置を覚えてしまわないよう、選択肢は出すたびに並べ直す。
    保存済みの問題をそのまま出すので、**復習だけはAPIキーがなくても解ける**
12. **教材**: スキルごと1件。作り直すと上書きする。教材が読めるのは「解放済み + 解放できる」勉強スキル
13. **AIの書き方の不具合は、コードの検査ではなく指示で防ぐ**:
    実際に出題させて見つかった不具合は、`quiz-gen.js` の `FORMAT_RULES` と
    `material-gen.js` の `TEXT_RULES` にルールを足して直す。
    `sanitizeQuestions` での機械的な検査は、形が壊れた問題を捨てるためだけに使う
    (文章の良し悪しはコードで判定できないため)。
    確認問題の文言ルールは `QuizGen._baseSystem` 経由で共有しているので、
    ここに足すと解放テスト・復習テスト・診断テストにも同じ指示が効く。
    これまでに足したルール:
    - 一つの問題(説明)の中で使う文字を最後まで変えない。ずれたら「読み替えて」と
      言い足さず、初めから書き直す
    - 添字が式になるときは `a_(n+1)` と書く(`a_n+1` は「a_n + 1」と読めるため)
    - 定数に `a_0` のような項の記法を流用しない(項の番号と紛らわしい)
    - 任意定数の置き方が違うだけの同値な選択肢を並べない
      (`(A+Bn)×2^(n-1)` と `(A+Bn)×2^n` はどちらも正解になってしまう)
    - explanation で選択肢に番号で触れるときは、番号と中身を照合してから書く
