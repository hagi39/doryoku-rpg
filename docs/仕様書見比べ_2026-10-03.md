# 再設計版仕様書と今のアプリの見比べ(2026-10-03)

作者(このアプリを遊んでいる人)が書いた「努力RPG 仕様書(再設計版)」と、
この時点のアプリを見比べた調査の記録。コードは変えていない。

## 前提

- 見比べたコード: `a6202be`(草原・海・コインまで公開済み)
- 仕様書: 「努力RPG 仕様書(再設計版)」PDF、13ページ・0〜14章。まだリポジトリには入れていない
- 仕様書の表記: 【決定】作者が決めたこと/【要望】細部は相談しながら決めてよいこと/【検討中】必ず作者に確認すること
- 作業の方針は変わらない。一つずつ公開し、公開前にセーブ互換をテストで確かめる

## B. あるが、作り方や考え方が違う部分

### B1. サビの仕組み(5章)。いちばん大きな違い

- 今のアプリ: 「最後に磨いた日」からの日数で、サビが0〜100%へ**少しずつ**進む。
  サビ始めるまでの日数は「2+2×磨いた回数」日(最大22日)、真っ赤になるまでは「10+2×回数」日。
  磨いた回数は**増えるだけで、減らない**
- 仕様書: 正解するたびに次にサビるまでの期間が **1日→3日→7日→14日→30日** と延び、
  **不正解だと短く戻る**。数値は調整できるようにする。いわゆる間隔反復(単語カードアプリと同じ考え方)
- 仕様書にあって今ないもの: 不正解による短縮、図鑑の「あやしい」マーク(サビやすくなる)
- 今のアプリでサビが落ちるのは「記録」と「復習テスト合格」の2つだけ。
  確認問題・復習リスト・世界地図では落ちない(README判断10番)。
  仕様書の「正解するたびに」をそのまま読むと、ここも変わる
- **セーブ互換に注意**: 今のセーブには `polishCount` と `polishedAt` しかない。新方式に移るときの換算ルールが必要

### B2. 経験値が「記録したこと」に付いている(13章の重要ルールと食い違い)

- 今のアプリ: 記録タブで「新しい挑戦/練習/復習のみ」を選んで記録すると、
  **自己申告で**経験値とパラメーターが入り、サビも0に戻る
- 仕様書13章: 報酬は「記録した・時間を使った」ではなく「**実際に達成した**(正解した・記録を更新した)」に付ける
- 今のゲームの土台にかかわるので、作者と方針を決めてから触る(D-2)

### B3. 筋トレ(11章)

- 今のアプリ: スキルと種類を選んで記録するだけ。回数や重さの数字は持っていない
- 仕様書: 「ボス=前回の自分」(前回の記録をわずかに上回ると勝ち)と休息バフ。**数字を記録する仕組み**が新しく必要

### B4. 問題の出どころ

- 今のアプリ: 問題は毎回AIがその場で作る。人の確認は通っていない
- 仕様書: 「自作、またはAIが生成したものを**確認して**使う」(0章)。
  公式は「教科書などで正しさを確認した固定データ」(6章)
- ハードモードの周回には「大量の問題」の**問題集(固定データ)**が要るので、作り方が変わる。
  今のAI出題は、学ぶタブや解放テストではそのまま使える見込み

### B5. データの持ち方(1章・14章の1)

- 今のアプリ: ツリーはJSの中にデータとして書いてあり、設定タブでJSONとして編集できる。配布は単一HTML
- 仕様書: ツリー・問題・公式・使うサイン・モンスターをJSONなどの別ファイルにして、コードを変えずに追加する
- 方向は同じ。「別ファイルのJSONを、ビルドのときに1枚のHTMLへ埋め込む」形にすれば
  `file://` 対応も保てる見込み(まだ試していない)

### B6. 記述問題の答え合わせ(7章)

- 今のアプリ: 表記をそろえて比べている(全角/半角、小数と分数、因数の順番など)
- 仕様書: 「式として等しいか」で判定するのが理想(`2x` と `x×2`)。今は**式どうしの同値判定はしていない**

### B7. 診断のやり方(8章)

- 今のアプリ: 「ここまでできる」をボタンで選ぶ形
- 仕様書: 「AIが自己評価を聞いて」とあり、会話形式を想定しているのかもしれない。小さな違い

### B8. コイン(とショップの予定)

- 仕様書には**コインもショップも出てこない**。報酬は装備・ペットのドロップ
- 今のアプリはコインを公開済みで、README では次に作るのがショップ(D-1)

## C. 今のアプリにない、新しく作る部分(14章の実装順に並べた)

大きさの目安(どれも推測で、細部の決め方で変わる)。**小**=1回の公開、**中**=2〜3回、**大**=何回にも分けて公開。

| 順 | 内容 | 大きさ | メモ |
|---|---|---|---|
| 1 | 土台:データ形式(ツリー・問題・公式・使うサインをJSONに)+ KaTeX表示 | 中 | KaTeXはフォントごとHTMLに埋め込む必要がある。ファイルが数百KB増える見込み(未計測)。スキルに「基礎(ドロップ率アップの対象外)か」の項目を足す |
| 2 | 勉強用キーパッド(分数の枠・カーソル移動・タブ切り替え) | 中〜大 | 自作か MathLive などのライブラリかは、**比べて作者に提案する**と仕様書にある。式の同値判定(B6)もここに関係する |
| 3 | 公式図鑑(全公式の閲覧・検索・覚えた/あやしい)+ 新しいサビ(B1) | 大 | **公式データを正しく書いて確認する作業**がいちばん重い(誰が確認するかも決める) |
| 4 | 問題形式:穴埋め・公式当て・次の一手・間違い探し(タップ) | 中 | 今は「選択」と「記述」の2種類だけ |

| 6 | 戦闘:冒険モードの充実 → ハードモードダンジョン(スキル選択、前提スキルの自動追加、複合問題、レア度つきドロップ、装備、天井、重複を素材に変換、排出率の表示、周回) | 大 | 装備とドロップはセーブの形が大きく変わる。会心・コンボ・効果音もここ |

| 8 | AI辞書(公式カードの「もっと詳しく」)・予言スキル・ペットに教える(AIが採点) | 中 | AI呼び出しの仕組みはもうある。接続方法は D の【検討中】1 で確認 |

14章の順番に入っていない要望もある。筋トレのボスと休息バフ(B3)、作戦会議・現実クエスト(12章)、
実績・隠しステージ・ペットのヒント役と救済役(10章)。

## D. 作者への確認が必要な部分

### 仕様書で【検討中】になっているもの(勝手に決めない)

1. **AIへの接続方法・料金・設定(6章)**。今は各自のAPIキーを設定タブに入れる方式。将来は有料機能にする可能性がある
2. **12章の【検討中】**: ミニクエスト(2分版)、連続記録の救済アイテム、ボス戦、冒険の書(毎日の振り返り)、キャラクターの見た目や装備

### 【検討中】ではないが、今のアプリと食い違うので確認したいこと

- **D-1. コインとショップはどうするか。** 次に作る予定のショップに着手する前に聞く。
  仕様書の「装備・ドロップ」に置き換えるのか、併存させるのか
- **D-2. 「記録すると経験値」(B2)を今後どう扱うか。** 消すのか、筋トレだけ残すのか、
  「記録更新」のように達成と結びつけるのか。今のセーブで貯めた経験値の扱いも一緒に決める
- **D-3. 新しいサビ(B1)の細かいところ。** 不正解で「短く戻す」のは1段階戻すのか最初からか。
  今の「少しずつ赤くなる」見た目を残すか。今のセーブからの換算をどうするか
- **D-4. 冒険の砂漠から先。** README の表(敵・条件・ペット)のまま進めてよいか。
  冒険モードに「思い出し問題」や「補習クエスト」を入れる形(2章)との関係
- **D-5. 公式データの確認者と範囲。** まず数学の何単元からか
- **D-6. 「実装時に提案してよい」とされている項目。** キーパッドの方式、レア度の段階数と名前、技のビルドの細部。
  決めてから作るので、案を出して選んでもらう形がよさそう
- **D-7. 仕様書と README の関係。** Artifact版で試作した機能(師匠チャット、カレンダー日記、成長グラフ、称号、効果音など)のうち、
  仕様書に入っていないもの(師匠チャット、カレンダー日記、成長グラフ)はまだ欲しいか
